Vibe-locked? Take your app with you.

Unvibe points at a vibe-coded app you own, records what it does, and rebuilds it as a real, self-hostable repo — same routes, same data, same flows. No platform lock-in. No copied code.

How it works

Four stages. The spec in the middle is the product's contract: versioned, human-readable, and checked into every output repo.

01 · CAPTURE

Record behavior

Headless browser crawls routes, records HAR traffic, downloads assets, screenshots every page.

deterministic · Playwright
02 · ANALYZE

Spec, not source

Route map, API inventory, data-model inference, auth detection → versioned unvibe-spec.json.

deterministic · REA eyes
03 · REGENERATE

Rebuild clean-room

Your LLM writes fresh React+TS from the spec only — it never sees platform bundle text.

BYOK · template-bounded
04 · VERIFY

Prove it

Screenshot-diff per route plus contract tests against the inferred API shapes.

pixelmatch · contracts

Try it

v1 targets *.lovable.app. Unvibe only processes apps you own — --i-own-this or an interactive attestation is required.

npx unvibe run \
  --url https://your-app.lovable.app \
  --i-own-this \
  --work-dir ./my-rebuild \
  --llm-provider openai --model gpt-4o-mini   # UNVIBE_API_KEY, or: --llm-provider mock

cd my-rebuild/repo
cp .env.example .env   # your keys, your instances
npm install && npm run dev
docker compose up -d   # self-hosted Postgres
